Test cases

CP-01 · Basic inference — PASS

Prompt: simple factual question asking the capital of France. Model answered “Paris”. Recorded prompt processing: 140.7 tokens/s; generation: 61.6 tokens/s. Single-run observation only.

CP-02 · Structured tool arguments — 15/15 recorded

Earlier bounded short-prompt set: 15 valid argument outputs out of 15. This is not a 15/15 autonomous task success rate and does not measure endpoint correctness, authorization reasoning, or execution.

CP-03 · BOLA invoice reasoning — NOT SCORED

Scenario used Alice's token against GET /api/invoices/1001 and GET /api/invoices/2002. A 10-point rubric was prepared covering classification/CWE, authorization boundary, evidence vs assumptions, validation, remediation, and severity. The final verdict and score were not preserved. Do not count this as a pass.

CP-04 · Tool-loop integration — FAIL
  • Inference API HTTP status: 200
  • finish_reason: length
  • Completion tokens: 500
  • Emitted plain text: functions.api_request({method:"GET",path:"/api/invoices/INV-101",token:"alice_token"})
  • Structured tool_calls field: not emitted

The response was not a valid machine-readable tool invocation and was terminated by the token limit.

CyberPal's earlier 15/15 structured-argument result and later tool-loop failure are separate test events. Do not average them into a single accuracy figure.

Build and model-loading preparation

Reported artifact size approximately 21.71 GB. CMake configuration stopped before compilation because CUDA::cuda_driver target was missing. CUDA compiler, SM75, and NCCL detection had succeeded. A 2,048-token context and explicit multi-GPU split were planned. The build issue is separate from the autonomous discovery result.

Why there is no BOLA accuracy percentage

CyberPal's invoice scenario has no preserved final verdict. RavenX did not reach a valid object endpoint. There is no complete labeled set of vulnerable and secure cases with true positives, false positives, false negatives, and true negatives. Therefore precision, recall, F1, and accuracy cannot be calculated honestly.

Missing raw evidence
  • Complete raw prompts and responses for every trial.
  • Per-model peak VRAM and GPU utilization time series.
  • Comparable RavenX prompt/generation tokens per second.
  • CyberPal BOLA rubric score and final verdict.
  • Complete RavenX request/response body archive and ground-truth route manifest.
  • Versioned vulnerable/secure test fixture and labels.

Next benchmark protocol

  1. Use an explicitly authorized deterministic API fixture with documented routes and Alice/Bob test identities.
  2. Seed known vulnerable and secure objects with ground-truth ownership/permission rules.
  3. Confirm owner access, then test cross-user read and separately write/delete/action on disposable fixtures.
  4. Capture request, identity, response, body fingerprint and server-side ownership ground truth.
  5. Require schema-valid tool proposals and enforce scope/budgets in the controller.
  6. Use a deterministic verifier for the final finding decision.
  7. Report TP, FP, FN, TN, precision, recall, F1, endpoint coverage, valid tool-call rate, and cost, with sample sizes and confidence intervals.
Do not treat guessed-route 404 responses as successful coverage. Do not treat a model's own assertion as the ground truth.
